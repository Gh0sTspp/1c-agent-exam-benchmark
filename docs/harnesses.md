# Харнесы: поставляемые описания

Харнес — набор инструментов, который получает агент на экзамене: MCP-сервер, skills или
то и другое. Каждый харнес описан одним файлом `harnesses/<id>.json`. Стенд читает эти
файлы и в шаге «Харнесы» страницы «Замер» показывает кнопку «Подготовить» у каждого
харнеса, для которого есть пакет под текущую ОС.

Подготовка одного харнеса:

1. скачать файлы из `downloads` в `.local/downloads/harnesses/` и сверить размер и SHA-256;
2. выполнить шаги `install` в `.local/harnesses/<id>/package`;
3. записать слепок пакета и профиль установки в `.local/harnesses/<id>/` — у каждой машины свои,
   в Git ничего не меняется;
4. запустить проверку на каркасе без обращения к модели и сохранить квитанцию
   `.local/harnesses/<id>/capability.json`.

Только харнес с принятой квитанцией появляется в выборе окружения для экзамена.
Установленный пакет не перезаписывается: при изменении он не пройдёт сверку слепка.
Чтобы переустановить харнес, удалите `.local/harnesses/<id>/`.

Командная строка делает то же самое:

```sh
python tools/prepare_native_harnesses.py --list
python tools/prepare_native_harnesses.py --install --check bsl-analyzer-0.3.2
```

Если скачивание не удалось или оборвалось, стенд повторяет его ещё три раза: через 5, 15
и 45 секунд. Файл релиза (`github.com/.../releases/download/...`) докачивается с места
обрыва, архив с `codeload.github.com` скачивается заново. Если и это не помогло, скачайте
файл другим способом и положите его в `.local/downloads/harnesses/<имя из downloads>`,
например `.local/downloads/harnesses/unica-package.zip`. Файл, который уже лежит там,
стенд не скачивает, а только сверяет его размер и SHA-256.

## Формат

```json
{
  "schema_version": 1,
  "id": "my-harness-1.0.0",
  "label": "Мой харнес 1.0",
  "version": "1.0.0",
  "homepage": "https://github.com/me/my-harness",
  "description": "Одна фраза: что получает агент.",
  "probe": {"tool": "list_objects", "arguments": {"path": "{src}"}, "expect": "Catalog"},
  "targets": {
    "windows-x64": {
      "downloads": {
        "my-harness.zip": {"url": "https://github.com/me/my-harness/releases/download/v1.0.0/win.zip",
                           "sha256": "<64 hex>", "bytes": 123456}
      },
      "install": [{"unzip": "my-harness.zip", "to": "."}],
      "configuration": {
        "version": "1.0.0",
        "label": "Мой харнес 1.0",
        "server": "my-harness",
        "command": "{package}/my-harness.exe",
        "args": ["mcp", "--src", "{src}"],
        "env": {"MY_CACHE": "{tmp}/my-harness"},
        "registration": "Официальный релиз; MCP только по рабочей папке"
      }
    }
  }
}
```

- `id` совпадает с именем файла.
- Ключ цели — `<ОС>-<архитектура>`: `windows-x64`, `linux-x64`, `macos-arm64`, `macos-x64`.
  Харнес без цели для текущей ОС показывается недоступным.
- Все URL — `https://`, у каждого файла закреплён SHA-256.
- `bytes` — размер файла. По нему стенд видит оборванную передачу до подсчёта SHA-256;
  без него файл не докачивается, а скачивается заново.

### Шаги установки

Разрешены только перечисленные шаги; произвольные скрипты пакета не запускаются.
Пути `to` — внутри папки пакета.

| Шаг | Что делает |
|---|---|
| `{"copy": "<файл>", "to": "<путь>", "executable": true}` | копирует скачанный файл; `executable` — сделать исполняемым (macOS/Linux) |
| `{"unzip": "<архив>", "to": "<папка>"}` | распаковывает ZIP в пакет |
| `{"untar": "<архив .tar.gz>", "to": "<папка>"}` | распаковывает tar.gz в пакет (без ссылок наружу и устройств) |
| `{"unzip-source": "<архив>"}` | распаковывает ZIP во временную папку исходников |
| `{"copy-tree": "<glob в исходниках>", "to": "<папка>"}` | копирует папку из исходников |
| `{"verified-entrypoint": "<tar.gz>", "manifest": "<json>", "to": "<файл>"}` | извлекает исполняемый файл и сверяет его хеш с манифестом релиза |
| `{"pip": "<requirements в репозитории>", "to": "<папка>"}` | ставит закреплённые Python-зависимости в папку пакета |
| `{"pip-source": "<glob в исходниках>", "to": "<папка>"}` | ставит сам Python-проект без зависимостей |
| `{"node": "<путь>"}` | копирует найденный `node` в пакет |
| `{"npm-lock": "<папка>"}` | ставит npm-зависимости строго по `package-lock.json` с проверкой integrity |
| `{"github-tree": "<owner/repo>", "commit": "<sha>", "prefix": "<путь/>", "to": "<папка>"}` | скачивает файлы репозитория на закреплённом коммите |

### Конфигурация запуска

`configuration` попадает в рабочую папку агента. Подстановки: `{package}` — копия пакета,
`{workspace}` — рабочая папка, `{src}` — выгрузка конфигурации, `{tmp}` — временная папка,
`{python}`, `{python_bin}`, `{platform}` — путь к 1С. `server` регистрирует MCP-сервер для
Codex, `skills` — папку со skills внутри пакета.

### Проверка

`probe` — либо имя встроенной проверки (`unica`, `rlm`, `bsl-analyzer`, `bsl-ls`, `code-index`,
`skill-script`, `toolkit`), либо описание вызова MCP: `tool`, `arguments` (можно `{src}`)
и необязательная строка `expect`, которая должна быть в ответе. Без `probe` достаточно,
чтобы сервер стартовал и вернул непустой список инструментов, а у харнеса только из skills —
чтобы в объявленной папке нашёлся хотя бы один `SKILL.md`.

## Как предложить свой харнес

Проще всего — кнопка «Добавить харнес» на странице «Замер»: она показывает готовый промпт
для вашего агента (Codex или Claude Code). Скопируйте его, допишите в конце параметры
харнеса — агент создаст описание, установит харнес и проверит его.

Добавьте `harnesses/<id>.json`, подготовьте его на своём стенде кнопкой «Подготовить»,
сделайте замер и отправьте PR с описанием и результатом. Результаты с новым харнесом
попадают в рейтинг отдельной строкой со ссылкой на его страницу.
